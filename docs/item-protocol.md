## 응답 규약: 사안 분리

사용자는 응답을 사안 카드로 나눠 보고, 카드마다 따로 처리해 한 번에 답한다. 그래서 응답은 사용자가 결정할 단위로 나눠 쓴다.

```
전체 흐름을 짚는 종합 의견. 1~5줄, 필요할 때만

### [제안] 합산 시 가격은 새 값으로 덮어쓰기 (← #2-3)
해 본 결과, 근거, 선택지, 영향
```

- 종류
  - [질문]: 사용자의 판단이나 정보가 있어야 진행할 수 있는 것
  - [제안]: 승인을 받고 진행하려는 것
  - [보고]: 한 일과 알게 된 사실. 확인만 받으면 되는 것
- 사안 하나에는 결정 하나를 담는다. 제목만 읽어도 무엇을 결정하는지 알 수 있게 쓰고, 근거와 선택지는 본문에 쓴다
- 지시를 수행한 결과와 그에 따른 제안은 한 사안에 함께 쓴다. 결정할 것이 있으면 그 사안을 [제안]이나 [질문]으로 쓴다
- 이전 사안에서 이어진 사안은 제목 끝에 출처 `(← #ID)` 를 붙인다. 한 사안에서 결정이 여럿 나오면 각각 같은 출처를 붙인다
- 응답은 마지막 사안의 본문으로 끝낸다
- 짧은 물음에 답할 때는 [보고] 하나로 쓴다
- 맡은 일이 끝나 처리할 사안이 더 없으면 다음 할 일을 묻는 [질문] 하나를 쓴다. 정리할 시점이면 `/clear` 를 권하는 [제안] 하나를 쓰고, 남길 결정은 [D], [W] 로 함께 올린다

## 사용자 답장

사안마다 `#2-3 [제안] 제목 → 승인: 덧붙인 말` 처럼 한 줄로 온다. 처리는 답변, 승인, 보류, 기각, 확인이다. 덧붙인 말 없이 확인한 사안은 `확인: #ID, #ID 사안 종료됨.` 한 줄로 묶여 온다.

- 확인으로 끝난 사안은 응답에서 다루지 않고 다음 일로 넘어간다. 확인에 덧붙인 말이 있으면 그 말에만 답한다
- 기각된 사안은 사유를 반영하고 다른 방향을 찾는다. 제안하기 전에 `overseer` 도구 `decisions` (action "reject")로 비슷한 제안이 기각된 적이 있는지 본다
- 보류된 사안은 사용자가 다시 꺼낼 때까지 손대지 않는다

## 보존 사안: [D] 결정 기록, [W] 용어

다음 세션에도 유효한 결정과 용어는 보존 사안으로 올린다. 사용자가 승인하면 패널이 보존하고, 세션을 시작할 때마다 목록으로 넣어 준다. 목록이 매번 들어가니 제목은 짧게 쓴다.

```
### [제안][D] 같은 이름 재추가 시 수량은 합산, 가격은 새 값으로
근거: #2-2
대체: D-3
```

- [D] 제목: 결정 한 줄, 60자 이내. 이유는 근거 사안에 있으니 결정만 쓴다
- [W] 제목: `용어: 뜻`, 뜻은 20자 안팎
- `근거:` 에는 사용자가 실제로 결정한 사안 ID 를 쓴다. 사용자가 결정한 것만 올린다
- 받은 목록과 다르게 정하려면 `대체: <기록 ID>` 를 붙여 올린다
- 보존은 패널이 맡는다. 승인된 기록은 패널에만 두고, CLAUDE.md 나 메모리에는 옮겨 적지 않는다
- 기록의 이력과 근거는 `overseer` 도구 `record`, 목록과 검색은 `records` 로 본다
